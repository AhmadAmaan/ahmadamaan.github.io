PROJECT 03 / ROUTE PLANNING · BACKEND API

Fuelwise

A Django API that plans US road trips with fuel stops, purchase quantities, cost estimates, and interactive maps. It combines road routing, station identity matching, spatial search, fuel-range validation, caching, and a bounded detour search when the direct route lacks coverage.

Explore the code ↗

The problem

A route with cheap fuel is only useful if the vehicle can reach every stop and the station data refers to real locations. Fuelwise combines cost planning with road-distance checks and explicit data-coverage reporting.

Inside the build

  • Validate the physical itinerary. OSRM supplies road geometry. The planner searches nearby stations, selects purchases, then recalculates fuel needs from actual routed legs and rejects unreachable plans.
  • Treat station identity as a data problem. The import process matches station identifiers to retailer directories and geographic records. Ambiguous matches are excluded rather than silently placed at city centres.
  • Bound expensive routing work. Caching, request coalescing, and a small routing-call budget limit external work. Where coverage is sparse, a bounded graph search proposes a detour that is subsequently checked against road distances.

Scope & trade-offs

The dataset has partial geographic coverage, so some trips require detours or cannot be planned. Fuel-purchase optimization applies to a fixed ordered itinerary; selecting the overall itinerary is heuristic. The demo uses fixed vehicle assumptions and a car routing profile.

What I’d explore next

Improve verified station coverage, support configurable vehicle models, and move the cache and rate coordination to shared infrastructure for multi-host deployment.
